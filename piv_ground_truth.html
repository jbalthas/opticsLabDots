Intensity/diameter drawn from N(1, σ) per particle. Out-of-plane: fraction of particles dropped from the frame entirely (not dimmed), re-drawn each camera frame — models light-sheet loss.

A particle that crosses the periodic boundary between Frame A and Frame B is unpaired — it adds noise to the correlation instead of signal. Unavoidable at the edges of any periodic synthetic field and normally small, but it is part of the stimulus, so it is measured and stated here rather than left to be discovered. Return to origin is the old recycling behaviour, now off by default: every flow here is incompressible so the field cannot clump, which made the extra teleport redundant while it injected unpaired particles at an unreported rate.

Enter the window your PIV package uses, in camera pixels, and the imaging scale. A 32 px camera window on a camera resolving the screen at 0.5 cam-px per display-px covers 64 display pixels — twice the field, four times the particles and a different gradient bias, so this conversion is not optional.
A PIV correlation returns a window-averaged displacement, not the velocity at a point. For any flow with curvature the two differ, and comparing a window-averaged measurement against a point-valued truth books that difference as algorithm error when it is nothing of the kind. Set this to your package's final-pass window and read the window-averaged truth in the bottom bar. NI ≳ 8 and Δ ≲ IW/4 are the usual working limits.
Image Noise
Read noise: zero-mean Gaussian σ in DN, added after display encode. Shot: zero-mean, signal-dependent — σ = √(scale · Ilocal), drawn per pixel from the accumulated intensity. Background: uniform DN pedestal. A fresh realisation is drawn every rendered frame, so Frame A and Frame B of a step-pair never share one.
Off (default) renders intensities directly as DN, so the light leaving the panel carries the Gaussian raised to the panel's gamma — the emitted particle image is narrower than the one specified. On, the particle field is composed in linear light and encoded with the inverse EOTF, so the emitted profile is the intended Gaussian. Set γ from the measured display gamma in the calibration protocol, not from the nameplate.

off
Sets the step rate to the measured refresh exactly, so the sim-time scale is 1.000 — but only once the interval measurement is good enough to be worth trusting. While the panel is unstable it refuses to lock and says why in the metrology panel; locking to a refresh measured through heavy jitter would bake a wrong number into the stimulus and then print a reassuring ×1.000 beside it. Camera fps is never set for you: it describes your physical camera, and writing a rate the camera is not actually at is the exact failure this tool exists to remove. It computes the correct rate and you apply it once the camera really is there.
Advances the sim by exactly 1/step-rate every rendered frame, decoupled from the wall clock — so the quoted displacement stops being an assertion. Set camera fps to the measured panel refresh, or an integer divisor of it. Open the metrology panel [T] for the live sync arithmetic.
Composites Frame A (red) and Frame B (green) into one displayed image — read Δpx by eye. A camera photographing this captures both in a single exposure, so it cannot produce a real PIV pair; use step-pair for that.
Step-Pair Capture
Steps a commanded displacement through a pixel as a sequence of pure-translation A/B pairs, so the measured-minus-commanded curve traces your package's peak-locking bias directly. This is the one measurement here that is about the algorithm rather than the display.
Shows only Frame A for the hold, then advances exactly 1/step-rate and shows only Frame B — temporally distinct, separately capturable frames. The frame-code top bit carries the phase (0 = A, 1 = B).
Frame Code
Clock block + 12 data blocks, LSB leftmost, pure #000 / #fff. Data encodes the rendered-frame index mod 4096; the clock block flips every rendered frame. Both copies encode the same index — if they disagree inside one captured image, the panel tore mid-refresh.
Timing Telemetry
Rolling 600-frame window of real requestAnimationFrame intervals: measured refresh, jitter σ, dropped frames, longest stall, and uΔt/Δt — the relative velocity uncertainty implied by timing alone.
Run Manifest
Writes every flow, particle, shape, variability, noise, timing, flume and obstacle parameter plus the seed, scale calibration and telemetry summary to JSON (schema v1). Importing restores the run — match the window size for a bit-identical field.
Scale Calibration
Your standard uncertainty on the panel's measured active-area dimension. This is the only part of the px→mm chain the tool cannot measure for itself, and it sets the spatial term in the stimulus uncertainty shown in the metrology panel.

Sub-pixel Sweep

Each point is a pure translation of one identical particle layout by an exactly commanded Δ. The flow field is not used. Every point restarts from the same snapshot, so nothing accumulates and the only variable across the sweep is the sub-pixel phase — which makes the structure in (measured − commanded) the algorithm's, with nothing else to blame it on.
Hold frames and step rate come from the Step-Pair section. An angle of 0 sweeps along x only, so y stays integer; 26.57° (atan ½) drives both axes off-lattice at once and is the more searching test.
